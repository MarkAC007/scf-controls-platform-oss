# v0.32.2

Fixes a fresh install that could come up healthy but unable to store credentials in the app: scripts/install.sh is now stated as a prerequisite for first run, the backend warns at startup when SCF_SECRET_KEY is missing, and an unattended install without a bootstrap admin email is rejected rather than producing an unusable stack. No migration; no configuration change.

## Fixes

**A fresh install could finish without an encryption key.** `SCF_SECRET_KEY` is
generated by `scripts/install.sh`, but the README's first-run instructions in the
catalogue section told you to run `docker compose up -d` without saying the installer
had to run first. Following them gave you a stack where every service reported healthy
and storing an integration credential in the UI failed with a `409`, often discovered
long after the install. The documentation now states the prerequisite, and
`install.example.json` ships as a template for `scripts/install.sh --unattended`, whose
configuration format was previously undocumented.

**The missing key is no longer silent.** The backend now logs a warning at startup when
`SCF_SECRET_KEY` is not configured, naming the consequence and the remedy. It is a
warning, not a failure: an installation that keeps its credentials in `.env` or in
environment variables is unaffected and continues to start normally.

**Unattended installs now require a bootstrap admin email.** With the bundled Keycloak,
`scripts/install.sh --unattended` accepted a configuration with no
`idp.bootstrap_admin_email`, then skipped creating the platform administrator. The stack
came up healthy with no organisation membership and an unusable UI. That configuration is
now rejected before anything is written, so you can correct the file and re-run.

## Upgrading

Nothing in this release requires action on an existing installation: there is no
migration, no new configuration, and no behaviour change beyond the startup warning.

If that warning does appear on your deployment, in-app storage of integration credentials
is unavailable until a key exists. Credentials you supply through `.env` or the
environment are unaffected and keep working, so this is only worth acting on if you want
to manage credentials from the Integrations page. See
[Credentials and secrets](https://markac007.github.io/scf-controls-platform/admin-guide/secrets/)
for the options.

- Run `scripts/upgrade.sh v0.32.2` (read `UPGRADING.md` first).
